[ЛОГИКА]
Git — это машина времени для проекта. Он хранит **снимки** состояния: сделал кусок работы — сохранил снимок с подписью. Всегда можно посмотреть, что менялось, и вернуться назад.

Четыре команды, которые покрывают 90% ежедневной работы:

```
git init                    завести репозиторий в этой папке
git status                  что изменилось и что попадёт в снимок
git add .                   выбрать всё изменённое
git commit -m "сообщение"   сохранить снимок с подписью
```

---

[ЛОГИКА]
Важная деталь, на которой все спотыкаются: `commit` сохраняет **не всю папку**, а только то, что ты добавил через `add`. Поэтому порядок всегда такой: `add`, потом `commit`.

Попробуй сделать коммит без `git add` — я покажу ровно ту ошибку, которую покажет настоящий git.

---

[ЛОГИКА]
Что нужно сделать в симуляторе:

1. `git init`
2. `git status` — посмотри, как выглядят неотслеживаемые файлы
3. `git add .`
4. `git commit -m "Первая версия сайта"`
5. `git log` — убедись, что снимок сохранился

Сообщение коммита пиши по-человечески: «Первая версия сайта», а не «test» и не «фикс».
