# Octavo-code

Открытая игра-тренажёр, в которой человек без опыта учится делать сайты: пишет HTML, CSS и JavaScript, собирает страницу из компонентов, чинит чужой лендинг, правит код через нейросеть, работает в консоли и выкладывает проект на GitHub Pages.

Главная идея: не «прочитал теорию», а **написал код — увидел результат**. В первой же главе курсор-маскот поднимается по лесенке, которую ученик собрал руками. Пропустил ступеньку — курсор застрянет, и проверка объяснит, на какой именно и почему.

Задание подаётся не стеной текста, а диалогом: реплики появляются по одной, у каждой свой голос — Курсор ведёт, Логика объясняет механику, Память возвращает к пройденному, Заказчик приносит требования.

## Что внутри

| Глава | О чём | Заданий |
|---|---|---|
| HTML | Из чего состоит страница, теги, вложенность, атрибуты, лесенка для курсора, файлы на диске, страница по описанию | 8 |
| Семантика | Суп из дивов, кто читает страницу кроме человека, article и section, nav и aside, несколько шапок на странице, расписание таблицей, починка полосы от нейросети — и статья по описанию заказчика | 9 |
| CSS | Селекторы, коробочная модель, flexbox, позиционирование ступенек, переменные, карточка по правилам | 7 |
| Композиция | Ловушка центра, выравнивание, поля, точка притяжения, сетка на CSS Grid, иерархия и масштаб, порядок чтения — и пять блоков настоящей страницы | 12 |
| Собираем как настоящие | Первый скрипт, чтение чужого кода, порядок компонентов, нейросеть, лендинг с багами, новый блок в чужом стиле, поведение по описанию, заказчик | 9 |
| Инструменты | Структура проекта, консоль и Node, git, GitHub, деплой на Pages, разбор чужой папки | 7 |

Глава про семантику проверяет не внешний вид, а смысл: страница из одних `div` выглядит ровно так же, как честная разметка, поэтому проверки там говорят не «не тот тег», а что именно потеряют программа чтения вслух и поисковый робот. Предпоследнее задание главы — починка чужой страницы: нейросеть прислала правдоподобную полосу, в которой сломан смысл, а не вид, и починить её нужно самому, а не поверить на слово.

Глава про композицию устроена иначе остальных: проверка там не говорит «неверно», а называет число — «левые края строк разъехались на 67px», «заголовок крупнее текста в 1.2 раза, нужно 2.5», «взгляд прыгает по горизонтали в среднем на 46px». Игра в том, чтобы свести числа к нулю. А кнопка «Путь взгляда» пускает курсор-маскот по композиции так, как её читает глаз: на центрированном тексте он мечется из стороны в сторону, на выровненном — падает ровно вниз.

Каждая глава заканчивается **итогом**: страница с нуля, в пустом файле, без примеров кода в брифе и без кнопки «Спросить нейросеть». Проверки в итоге названы умениями, а сообщения об ошибке ссылаются на задание главы, к которому стоит вернуться. Итог видно на карте: карточка подписана «итог главы».

Пять типов заданий:

- **код** — редактор с вкладками файлов и живое превью;
- **блоки** — сборка страницы из компонентов мышкой, результат сразу виден как настоящая разметка;
- **чтение кода** — найти строку с ошибкой и понять, что напечатает скрипт;
- **нейросеть** — составить запрос, принести ответ обратно, прочитать дифф и разобраться, что модель сделала на самом деле;
- **терминал** — симулятор консоли с виртуальной файловой системой и git: настоящие команды, настоящие ошибки, человеческие пояснения.

Главы не заперты прогрессом: любую можно открыть сразу. `requires` в манифесте остался советом («удобнее после»), а не замком.

## Быстрый старт

```bash
npm install
npm run dev
```

Откроется `http://localhost:5173`. Прогресс хранится в localStorage браузера — ни сервера, ни аккаунтов нет.

Другие команды:

```bash
npm test
```

```bash
npm run build
```

## Как это устроено

```
content/            задания и заказчики — правятся без знания кода движка
  global.json       глобальные параметры, общие для всех заданий
  chapters.json     главы и порядок
  tasks/<id>/       manifest.json, brief.ru.md, check.js, files/{start,solution}
  clients/<id>/     персона заказчика, ТЗ, критерии приёмки, правка по ходу
src/
  core/             реестр контента, песочница, проверки, прогресс, файлы, нейросеть
  core/runtime/     код, исполняемый внутри песочницы (тот же и в браузере, и в тестах)
  core/terminal/    симулятор консоли и git — чистые функции, без DOM
  ui/               экраны, диалоговое окно и раннеры заданий
tests/              проверка контента, ядра, парсера реплик и симулятора консоли
```

### Песочница

Превью — это `<iframe sandbox="allow-scripts allow-forms allow-popups allow-popups-to-escape-sandbox">` **без** `allow-same-origin`. Код ученика (и код, принесённый от нейросети) не видит страницу игры, её localStorage и прогресс. Обратная сторона: родитель тоже не видит DOM песочницы, поэтому проверки исполняются **внутри** неё — см. [`src/core/runtime/runtime.js`](src/core/runtime/runtime.js). Наружу уходит только результат, а бесконечный цикл в коде ученика ловится таймаутом и не вешает игру. Внешние ссылки без `target="_blank"` рантайм перехватывает и открывает сам — иначе такой клик увёл бы из-под ученика само превью.

Тем же путём работают задания с блоками и терминалом: раннер собирает страницу-снимок (вёрстку или состояние консоли в JSON) и отдаёт её в песочницу. Механизм проверок в игре ровно один.

### Проверки

`check.js` каждого задания — обычный JS, который регистрирует проверки:

```js
check('steps-count', 'На странице пять ступенек', function (t) {
  var steps = t.$$('.step');
  t.assert(steps.length === 5, 'Нашёл ступенек: ' + steps.length + ', а нужно ровно 5.');
  return 'Ступенек: 5';
});
```

Сообщение об ошибке — часть задания: оно должно объяснять, что именно не так, а не сообщать «неверно». Проверки, которым нужен настоящий браузер (геометрия, вычисленные стили), объявляются через `check.browser(...)` — в тестах они пропускаются.

### Нейросеть

Только копипаст: игра собирает запрос, ученик несёт его в любой чат и возвращает ответ, а игра показывает дифф до применения. Ключей игра не спрашивает и никуда не ходит по сети — ни общего ключа, ни своего, ни прокси в проекте нет и не будет. Нейросетью ученик пользуется у себя: в браузере или на своём компьютере. Это и есть навык, которому учит игра.

### Архив промптов

Отдельный экран (закреплён на главной, адрес `#/prompts`) с готовыми запросами для типовых ситуаций: объяснить чужой код, найти баг, дописать блок в существующем стиле, разобрать ошибку в консоли, распутать git. Тот же архив открывается кнопкой из панели «Спросить нейросеть» — оттуда промпт можно дописать прямо к собранному запросу.

Каждый промпт — markdown-файл в `content/prompts/`:

```markdown
---
title: Объясни этот код построчно
summary: Код работает, но непонятно почему.
tags: чтение кода, обучение
---
Объясни этот код построчно. Я новичок…
```

Положил файл — он появился в архиве. Ни кода, ни регистрации нигде править не нужно.

## Оформление

Тема одна — ночная. Переключателя нет: меньше кода, одна проверенная палитра вместо двух.

| Токен | Значение | Роль |
|---|---|---|
| `--paper` | `#101011` | фон страницы |
| `--paper-raised` | `#1a1a1c` | карточки и панели |
| `--paper-sunk` | `#0a0a0b` | углубления: поля ввода, полосы |
| `--plum` | `#fff9e4` | акценты, маскот, прогресс |
| `--ink` | `#f5f5f5` | основной текст |
| `--muted` | `#b3b0b2` | вторичный текст |
| `--inverse` | `#17171a` | диалог, консоль, терминал |

Поверхности различаются светлотой, а не оттенком: страница темнее всего, карточки чуть светлее, углубления темнее страницы.

Заголовки и реплики — Cormorant Garamond, интерфейс — системный шрифт, код и терминал — JetBrains Mono. Все токены лежат в [`src/styles/tokens.css`](src/styles/tokens.css) и больше нигде: цвет в компоненте — повод его туда вынести. Подсветка кода в редакторе тоже собрана из токенов (`--syn-*`), поэтому меняется вместе с ними.

## Как добавить своё задание

Скопируйте [`docs/task-template`](docs/task-template) в `content/tasks/<номер>-<id>/`, поправьте манифест, бриф, проверки и файлы — и всё, движок подхватит папку сам. Подробности и требования к качеству — в [CONTRIBUTING.md](CONTRIBUTING.md).
